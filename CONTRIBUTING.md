# WELCOME — помогите нам сломать WEDOAUDIO

Это открытая часть инструментария WEDOIT: ядро анализа звука и стенды, которые его проверяют. Мы выкладываем не только код, но и цифры, на которых он держится, — чтобы их можно было оспорить.

**Самый ценный вклад — трек, на котором стенд ошибается.** Не «мне кажется, реагирует не так», а воспроизводимый случай.

## За минуту: проверить, что у вас всё сходится

```
python src/_wedoaudio_test.py         # ядро, 14 тестов
python src/_wedoaudio_timbre_test.py  # тембр и тональность, 14 тестов
python src/_wedoaudio_bench.py        # стенд на синтезированных треках, 18 прогонов
python src/_wedoaudio_realtest.py     # аудио, которого мы не делали: точная разметка,
                                      # настоящая музыка, семь контейнеров
python src/_wedoaudio_libtest.py "D:/ваши/сэмплы"   # размеченная библиотека лупов
```

Первым трём нужен только numpy. Четвёртому — librosa и ffmpeg; без них он не запустится, и это нормально: остальные три полностью самодостаточны. Стенд печатает точность / полноту / F по каждому прогону и падает с ненулевым кодом, если результат опустился ниже записанной базы. Треки он синтезирует сам, поэтому прогон детерминированный: расхождение — это регресс, а не «тест мигает».

## Что мы просим сделать

**1. Добавить стиль.** Стенд синтезирует восемь секунд музыки и знает, где в них кики и снейры. Новый стиль — это одна ветка в `render()` в [`src/_wedoaudio_bench.py`](src/_wedoaudio_bench.py): положить удары через `place()` и записать их времена в списки. Мы заведомо не покрыли: свинг и триоли, трэп с быстрыми роллами, живой барабанщик с плавающей долей, полиритмию, дабстеп с половинной долей, металл с бласт-битами, спид-гараж, всё с сильной реверберацией. Каждый такой стиль либо подтверждает цифру, либо ломает её, и оба исхода полезны.

**0. Прогнать `_wedoaudio_libtest.py` на своей библиотеке.** Это самый дешёвый способ помочь и он занимает минуту. Любая пачка лупов, где в имени файла стоит BPM, годится как разметка от вендора. Пришлите вывод — особенно если ваши цифры хуже наших: значит на вашем материале что-то ломается, а у нас его нет.

**2. Принести настоящую запись.** Синтезированный снейр ведёт себя предсказуемее живого, и настоящей музыки с разметкой у нас нет ни одной — это самая большая дыра в проверке. Нужен трек и разметка ударов (хоть руками в Audacity, хоть Tab-клавишей под метроном). Формат: аудиофайл + текстовый файл, по времени в секундах на строку, отдельно кики, отдельно снейры. Права на трек должны быть ваши.

**3. Оспорить порог.** Все константы детекторов подобраны прогоном всего стенда — `src/_sweep.py` перебирает сетку и печатает F по каждой комбинации. Если ваш набор даёт другой оптимум, покажите таблицу: это разговор о числах, а не о вкусе.

**4. Найти ещё один дефект измерения.** Три уже найденных описаны в README, и все три — одного рода: величина мерялась не в той шкале. Абсолютный поток энергии там, где нужен относительный. Максимум бина там, где сигнал шумовой. Абсолютный пол логарифма там, где важна форма, а не громкость. Такие вещи не ловятся тестом «функция вернула число» — только измерением на материале.

## Как прислать

Pull request или issue на [github.com/ychkydyk/wedoaudio](https://github.com/ychkydyk/wedoaudio). В PR приложите вывод трёх команд выше до и после вашей правки — этого достаточно, отдельного описания не нужно.

## Правила, чтобы не было сюрпризов

- **Ничего не чиним на глаз.** Правка порога без замера не принимается, даже если она очевидно верная. Замер — это прогон стенда целиком, а не тот стиль, ради которого правка делалась.
- **Регресс важнее улучшения.** Если правка чинит один стиль и ломает другой, она не принимается, пока не показано, что размен выгоден. В README есть два случая, где мы сами на этом остановились.
- **Поведение по умолчанию меняется только под флагом.** Всё новое живёт в `cfg`, старое остаётся доступным одной строкой (`onset_rel = 0` возвращает поведение 4.2.0 целиком). Ригам в проде нельзя ломать вечер.
- **Ограничение, которое не удалось закрыть, пишется в README.** Открытым текстом, с цифрой. Незакрытое ограничение — не позор, а незакрытое и умолчанное — позор.

## Что открыто прямо сейчас

- Разрешение онсетов 16 мс: анализ идёт по кадрам 60 Гц. Для sample-tight вещей нужен отдельный путь по сэмплам. Единственное из четырёх исходных ограничений, которое ещё не закрыто.
- Темп на брейкбите читается как половина (88 вместо 174). Поддерживаемый диапазон объявлен: 68–200 BPM, медленнее — вдвое быстрее реального.
- АРУ держит примерно двенадцатикратный диапазон входа; тише — реакция падает вместе со входом.
- Громкость — спектральное приближение R128, а не сертифицированный R128.
- **Настоящей музыки с ручной разметкой у нас нет вообще.** Уровень B в `_realtest.py` сравнивает нас с librosa — это второе мнение, а не истина. Размеченный трек закрывает эту дыру сильнее любого кода.
- Тянущийся материал даёт ложные онсеты: дрон 2.27 ложных кика в секунду, атмосфера 1.62 ложных снейра. Самое заметное открытое место.
- Ключ на басовом материале — 3 из 13. Основной тон ниже окна хромы, обертоны уводят.
- Правите ядро — пересоберите компонент: `tools/build_portable.py` в TouchDesigner, потом проверка загрузкой в пустой контейнер с ДРУГИМ именем (должно быть 22 канала, самопроверка чистая, ноль ошибок).
